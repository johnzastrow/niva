# Heavy real-world data for harder niva benchmark runs

The benchmark suite runs out-of-the-box on **synthetic** data generated by
[`make_bigdata.py`](make_bigdata.py) — no network, deterministic, works on any clone. That's
enough to trace a scaling curve and compare machines.

To push niva **harder on real-world data** (irregular geometry, dense vertices, true raster size),
download one or more of the public datasets below into `data/` and point a flow at them, or copy a
test into your own suite. All are **open / public-domain**; pick by what you want to stress.

> Tip: drop the file in `data/` and reference it as `{data}/<file>` (the runners resolve `{data}`
> to `data/`). Sizes are approximate. Verify a download finished with the checksum command shown.

## Vectors

### Natural Earth — 10 m cultural & physical (global, public domain)
Dense global polygons/lines/points; good for `buffer`/`reproject`/`dissolve` at real scale.

```bash
# ~50 MB GeoPackage of all 10 m themes (admin, roads, rivers, lakes, populated places, …)
curl -L -o data/natural_earth_10m.gpkg \
  https://naciscdn.org/naturalearth/packages/natural_earth_vector.gpkg.zip
#   (the package is a .zip of a .gpkg; unzip if your mirror serves the archive)
```
Layers: `ne_10m_admin_0_countries` (~258 polys, very dense rings), `ne_10m_roads`,
`ne_10m_rivers_lake_centerlines`, `ne_10m_populated_places` — e.g.
`load "{data}/natural_earth_10m.gpkg|layername=ne_10m_admin_0_countries" | reproject EPSG:3857 | buffer 1000m`.

### OpenStreetMap extract (Geofabrik, ODbL) — a whole region
Hundreds of thousands of features; the heaviest realistic vector load. GeoFabrik ships `.osm.pbf`
(needs GDAL's OSM driver) and, for some regions, a ready `.gpkg`/`.shp.zip`.

```bash
# A small US state .osm.pbf (~50–100 MB) — Vermont is one of the smallest
curl -L -o data/vermont.osm.pbf \
  https://download.geofabrik.de/north-america/us/vermont-latest.osm.pbf
# Load a layer (OSM exposes points/lines/multipolygons/…):
#   load "{data}/vermont.osm.pbf|layername=lines" | simplify 5 | save out.gpkg
```

## Rasters

### Copernicus DEM GLO-30 (global 30 m elevation, free/open)
A real DEM tile for `warp` / `slope` / `aspect` / `hillshade` at full resolution.

```bash
# One 1°×1° tile (~25–60 MB GeoTIFF). Browse tiles at https://copernicus-dem-30m.s3.amazonaws.com/
TILE=Copernicus_DSM_COG_10_N43_00_W073_00_DEM
curl -L -o data/copernicus_dem.tif \
  "https://copernicus-dem-30m.s3.amazonaws.com/${TILE}/${TILE}.tif"
#   load "{data}/copernicus_dem.tif" | warp EPSG:3857 | slope | save slope.tif
```

### USGS 3DEP / a public Cloud-Optimized GeoTIFF (US, public domain)
Large single-band elevation COGs; good for streaming-read raster I/O.

```bash
# Example 1-arc-second tile (~400 MB uncompressed; COG so partial reads are cheap)
curl -L -o data/usgs_dem.tif \
  https://prd-tnm.s3.amazonaws.com/StagedProducts/Elevation/13/TIFF/current/n44w072/USGS_13_n44w072.tif
```

## How to point the benchmark at real data

1. Download a file above into `data/`.
2. Either add a `# ===== TEST NN | <dim> | … =====` block to
   [`benchmark_suite.niva`](benchmark_suite.niva) that loads `{data}/<file>`, or run a one-off:
   ```bash
   niva 'load "data/natural_earth_10m.gpkg|layername=ne_10m_admin_0_countries" \
         | reproject EPSG:3857 | buffer 5000m | save /tmp/ne_buf.gpkg'
   ```
3. The benchmark runner records wall/CPU/RSS/IO either way — compare against the synthetic-data
   baseline in `~/niva-test-results/benchmark_latest.md`.

> These downloads are **optional** and **never committed** (`data/` is gitignored). The suites
> remain fully runnable from a clone using only generated + committed data.
